# Qt 监控客户端

独立的 Qt Widgets 客户端，通过 Go signaling 管理设备、源和播放票据。支持 1/4/9/16 画面；实时输入为 RTSP/TCP，历史回放使用独占 HTTP chunked PS。FFmpeg 解码、Qt 呈现、SDL 播放声音。

构建依赖、命令和内部运行包见 [构建部署](../docs/build-deploy.md)，接口见 [信令 API](../docs/signaling-api.md)，身份及取消规则见 [媒体生命周期](../docs/media-lifecycle.md)。生产目标为 `gb_monitor`，旧桌面测试及探针目标已删除。

## 使用

- 启动后填入 signaling 地址（默认 `http://127.0.0.1:9090`），刷新设备；选中画面后双击或拖入通道/源。缩小布局会停止隐藏画面。
- 每个画面独立申请一次性票据；GB 点播等待同一 live 的 `media_ready`。停止画面只关闭该 viewer，不停止共享 GB live。
- 默认静音；声音按钮作用于当前画面。窗口拥有一个 SDL 音频设备，画面临时借用。停止或替换后需重新显式开声。
- 设备树选择决定查询、PTZ 和对讲目标。目录/信息/状态/预置位/录像均由用户显式查询；控制受理不等于设备完成动作。
- 录像查询后可选择独立回放或下载。按设备 UTC 偏移换算时间；回放支持同会话暂停、继续、相对定位与倍率请求，实际效果依赖设备。
- 实时本地录制使用另一张票据，从可解码关键帧流复制到 Matroska。下载使用独占历史实例和临时文件；只有完整结束才保存，取消或失败清理本次临时文件。
- 对讲先准备默认麦克风和 PCMA 编码，再申请 WebSocket 上传地址。停止、切平台或关窗只删除匹配的 talk_id；设备回传声音由实时画面的声音按钮独立控制。
- 报警页轮询内存报警；容量淘汰或服务重启可能丢失历史，不能用作持久化报警档案。

## 实现边界

视频只接受 H.264；音频接受 AAC、PCMA、PCMU，转为 48 kHz 双声道 S16。合法无音频源可播放，已声明的不支持音轨会失败。支持全屏、保持比例和当前显示图像抓图；偏好不保存播放票据或自动恢复播放。

停止/替换会销毁请求 context、取消 HTTP 并请求解码线程中断，GUI 不等待网络 join。迟到结果不能影响新的画面或历史实例。播放器本地操作身份不等于服务器媒体源身份；源结束后重开必须使用新 stream_id。

源码实现这些操作，不构成所有设备、倍率、H.265、物理声画或完整双向对讲的兼容性承诺。原型目录 `designs/` 是未跟踪本地资料，不作为构建依赖。
