# WHEP CORS 边界

## 背景

WHEP 播放通常由网页发起，而网页 origin 与媒体服务器地址经常不同。创建会话使用 `application/sdp`，浏览器会先发送 CORS preflight；原实现把 `OPTIONS` 当成不支持的方法，因此浏览器无法到达已经可用的 WHEP POST/DELETE 流程。

## 决策

CORS 属于 HTTP 传输职责，只在 `http_session` 处理，不进入 `whep_service` 或媒体会话。当前接口没有认证、cookie 和用户数据，因此使用 `Access-Control-Allow-Origin: *`，不增加 origin 配置、credential 或 `Vary` 状态。

preflight 只广告当前真实支持的 `POST`、`DELETE`、`OPTIONS` 和 `application/sdp`。POST 暴露浏览器后续删除会话所需的 `Location`；PATCH、SDP fragment 和 Trickle ICE 仍不支持，也不在 CORS 响应中广告。

## 验证

回归测试通过真实 TCP 和 HTTP session 完成 preflight、创建、Location preflight、删除及重复删除，确保成功和错误响应都可被跨域调用方读取。
