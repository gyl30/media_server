## Fixed：媒体恢复提示与实际恢复动作不一致

分类 D / P2，三次独立环境故障与新浏览器上下文复现。

用户故事：值守人员正在看已上线摄像机，媒体服务停止后恢复。设备和通道仍显示在线、正在取流。用户按“媒体尚未就绪，请稍后重新播放”反复播放，仍失败；只有停止该通道取流后再播放才恢复。用户不应需要知道旧 live 与媒体接收端之间的内部关系，才能找到现有手动恢复动作。

三次干净复现均为旧取流重播收到两次 WHEP 409；两次请求使用不同 ticket，符合现有仅重新申请一次 ticket 的规则。旧 live 保持，手动停止再播放后新代画面均解码为 320×240、`readyState=4`。本轮不改变后端恢复政策。

根因是错误面板只提供稍后重播，没有提供持续失败时的操作路径。最终错误文案为：

> 媒体尚未就绪，请稍后重新播放；若持续失败，请点击通道中的“停止取流”后再播放（会影响该通道的其他观看者）。

只在已有 `whep_create_409` 且更新包含真实 `liveID` 的 GB 路径追加说明。RTSP 提示与 30 秒预算保持原样；不自动停止、不自动重连、不增加 ticket 重试。生产变化为 `signaling/web/app.js` 增加 3 行，无新长期状态、helper、回调或框架，Go/C++ 生产修改均为 0。

RED：在原基线管理服务上运行新增 E2E 场景，两次 409、旧 live 保持、PeerConnection 关闭和视频清空均成立，错误文案缺少“停止取流”和“观看者”的断言失败，实际仍是旧提示。

GREEN：使用修复后的管理服务，完整既有浏览器套件 37 项通过。新场景验证上述提示、共享影响说明、手动停止与再播放、新 live 代际以及真实媒体解码。修复后独立角色仅凭可见提示恢复 Office 画面，观看约 18 秒，再关闭播放器；通道仍在线、正在取流。后续正常值守持续验证未出现新增行为问题。

第二阶段之后另做 480px 窄窗定向复查，不计入普通使用时长：真实媒体重启后两个 fresh ticket 均为 409，新增说明完整可读；页面宽度 465px、窗口 480px。普通 `elementFromPoint` 指针命中通道“停止取流”按钮，实际点击后再播放解码为 320×240、`readyState=4`，随后视频时间推进。新取流首次 WHEP 仍为 409，既有一次 fresh ticket 重试返回 201，未增加重试。临时复查脚本最初同名文字严格匹配过宽、预设恢复只有一次 POST；修正断言后保留实际 `[409, 201]` 恢复响应，不把工具错误当产品问题。

## Accepted boundary：工作模型可以建立

- 添加设备成功不意味着平台主动连接设备。新配置离线等待 335.57 秒后，从设备侧接入；采样约 1.8 秒看到上线与通道。页面已给出检查设备网络和接入配置的下一步，没有诱导删除重建。
- 看完后“关闭播放器”是更自然的退出动作，通道继续取流。误点“停止取流”后画面结束、通道未取流，但直接播放可以恢复；学习后两种动作的范围稳定，没有增加确认或状态记忆。
- 五位置巡视中，后四处各两次点击、无需返回或主动关闭旧 viewer。二十台巡视共 40 次点击、两次列表滚动；时间跨中断，不用于比较操作速度。
- 正常设备离线后自动显示离线/结束；恢复接入后不 reload 即可手动播放。异常断电先出现冻结，控制面稍后判定离线；最后一次仍播放采样在 58.56 秒，114.18 秒采样已结束，不能把后者写成精确超时值。未改心跳或自动重连政策。
- 三个独立终端共享一路，首轮只有一次 INVITE。一个终端关闭 viewer 时，其他两个视频时间仍推进；停止共享取流后其他终端结束。一个用户手动再播放形成新代，另一个用户仍需主动播放加入；INVITE 总计两次。
- 管理服务故障时错误提示与停止推进的更新时间可以说明数据可能过期。恢复后 polling 更新，无需 reload；人工刷新只在这次故障中使用一次，平日自动刷新足够。
- 动态窗口宽度 1440→1000→800→600→480→800→1440，持续播放后仍可关闭、停止和编辑。Chrome 原生缩放 100/125/150/200% 下完成观看、切换与返回；不是 CSS zoom 或 deviceScaleFactor 模拟。
- 编辑 RTSP 后保持已停止，离开约 4.47 分钟回来仍能看到已停止/未取流及开始入口；没有自动启动。为只改显示名称付出的停止、编辑、保存、开始、再播放成本是真实摩擦，本轮不开放热编辑。
- 正式删除在线且有 live 的 GB 设备时，确认说明会停止该设备全部播放；设备与观看清理成功，旧 WHEP 资源返回 404。

## Preference / rejected finding

- 撤回“ended/failed 后关闭播放器可用就是资源错误”。当前关闭动作还用于收起已经释放 viewer 的结束面板；实测视频已清空，点击仅收起面板，无额外 DELETE。不能沿用旧目标的按钮状态表判断当前基线。
- 不因五十台列表有滚动就直接增加搜索；不因首次区分播放/关闭/停止时犹豫就改变共享生命周期。多次使用后动作范围稳定。
- 一次键盘任务误数 Tab 并确认删除了测试来源，是演练操作错误；取消确认可恢复，不列产品 correctness finding。
- 切回设备页短暂出现尚无通道，随后正常加载；两次切页瞬态观察、均无任务阻碍，不升级或顺手改渲染。

## 结论

最常完成的是“找到位置、播放、切换或关闭”。最自然的恢复是修正设备/地址后手动播放；持续 GB 409 的特殊恢复现在也由页面说明。P0/P1 为 0，确认 P2 为 1 且已修，保留两项 P3 边界。主要工作模型经过重复使用可以建立；后续修改应由真人任务数据、可复现 bug 或协议事实驱动。本轮没有新增产品功能。
