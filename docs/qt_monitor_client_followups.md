# Qt 监控客户端：当前能力与后续清单

2026-10-18 按用户要求整理：先稳定并合入已经实现的 Linux 客户端，未实现功能记录在此，不在本轮继续扩展。能力核对基线为 `b14ab49`。本清单区分代码缺失、已有实现的兼容限制、未验证边界及明确延期；不把旧阶段记录中的“未实现”自动当作今天的待办。

## 已实现，保留现有行为

- Linux x86_64 Qt Widgets、FFmpeg 解码、1/4/9/16 画面、H.264、AAC/PCMA/PCMU/合法无音轨；平台设备树、普通媒体源观看、声音、抓图及偏好。
- GB 目录、设备信息/状态、八方向点动、变倍、STOP、预置位查询/设置/调用/删除。
- 设备录像查询、独立回放、暂停/继续、同会话定位及基本倍率请求；按实际输入节奏呈现，不承诺设备的精确落点或实际倍率。
- 设备录像下载、本地 Matroska 流复制录制、取消与磁盘失败处理。
- 已注册设备主动报警的接收、协议响应及近期列表；Qt/Web 麦克风上传、内部 Broadcast SIP 控制和媒体服务器向设备发送 PCMA。
- 内部可搬运运行包、第二机播放及指定负载下的 16 路同时解码。内部包存在不等于公开发行许可已经闭合。

实现入口包括 `desktop/monitor_window.cpp`、`playback_view.cpp`、`record_query_dialog.cpp`、`record_thread.cpp`、`talk_session.cpp`，以及 `signaling/gb_ptz.go`、`gb_playback.go`、`alarm.go`、`gb_broadcast.go`、`gb_talk.go`。实际覆盖与限定结论见[七阶段当前收口表](qt_monitor_client_stage7_installed_controls.md#6-七阶段与审计收口)，完整使用方式见 [desktop/README.md](../desktop/README.md)。

## 未实现，留待独立任务

| 功能 | 当前缺口 | 后续实施边界 |
| --- | --- | --- |
| 高级云台控制 | 聚焦、光圈、巡航、看守位、拉框等没有完整生产入口；预置位名称写入未实现 | 现有 `encodePTZ` 白名单不等于全部 PTZ；按标准指令和实际硬件逐项增加，不放空按钮 |
| 报警查询/订阅/复位 | 目前仅接收主动 Alarm MESSAGE；没有完整 SUBSCRIBE/NOTIFY 订阅、设备报警查询及复位流程 | 不把现有近期列表查询当作设备查询或订阅；复位/布撤防要明确副作用 |
| 报警持久化 | 平台近期缓存最多 1000 条，Qt 最多显示 500 条；重启清空、淘汰可出现 gap | 若确需历史档案，再单独确定保留策略；现实现不承诺高频无损采集 |
| Catalog 订阅和增量通知 | 有主动查询与分批聚合，没有标准订阅完整生命周期 | 不以定时重新查询冒充订阅；后续需覆盖到期、取消和设备重注册 |
| MobilePosition 查询/订阅 | 无生产入口及相应设备验证 | 需要适用设备/角色；固定相机不保证有定位能力 |
| ConfigDownload 配置查询 | 没有完整只读配置查询接口与桌面展示 | 先选择明确的查询类型，不与写配置混为一谈 |
| DeviceConfig、RecordCmd、GuardCmd、AlarmCmd、TeleBoot 等管理命令 | 未提供完整生产控制入口 | 涉及配置、录像计划、安防状态或重启，另行确定授权与恢复方案，不在合并验收时探测 |
| 上下级联/跨平台资源共享 | 不属于本次 Qt 七阶段交付 | 需要独立明确平台角色和对端，不能用单相机测试替代 |
| GB/T 28181—2022 全量差异审查 | 当前增量主要依据 2016 版，未完成新版逐条角色/必选/可选映射 | 不宣称所有 GB28181 标准版本已通过符合性认证 |

这些项目是后续候选，并非本次合并新增门禁。实施前仍须证明实际需求、标准适用性、设备能力和最小改动范围。

## 已实现但存在限制或尚未验证

| 项目 | 准确状态 | 不能作出的结论 |
| --- | --- | --- |
| PTZ START 确认 | 当前 300ms 有界点动及独立 STOP 已实现；大华可能实际运动但 START 应答迟到，界面显示 `ptz_start_unconfirmed` | 不能把“未确认”写成未实现或已完成动作；不通过延长运动、盲重试或忽略失败掩盖兼容性 |
| 实体云台动作 | 实测左右点动、停止、预置位保存/调用归位/删除；变倍物理效果及其他动作没有全部实测 | 不承诺所有方向、所有硬件或 STOP 中断预置位调用均已验收 |
| 录像定位/倍率 | 指定大华库存内同会话 seek、2→1 倍率及实际双轨呈现有证据 | HTTP 204、请求值或下拉框不等于精确落点/实际倍率；不要求平台替设备保证精度 |
| 报警物理触发 | Qt→生产 HTTP→实际 UDP SIP 组合通过，真实相机物理报警触发尚未验收 | 协议组合不是物理报警触发证明 |
| 双向对讲声学 | 上传、SIP、PCMA RTP、回看解码、数字 PCM 有限定证据；物理麦克风与设备扬声器及双向声学仍未闭合 | 不能把本地发送成功、设备方向 RTP 包数或数字回环当作真实听音通过 |
| 公开发行 | 内部包依赖和运行范围已记录；项目许可证和完整依赖源码交付材料仍有外部阻塞 | 本次代码合入 main 不等于可以公开分发二进制或宣布整产品无条件 GO |

原始源替换轮次的 PARTIAL/FAIL_CLEANUP，以及后续分别定位的 FFmpeg 信号退出、X11 隐藏弹窗误选等事实仍保留；新的限定通过不改写旧失败。参见[源替换记录](qt_monitor_client_stage7_source_cycle.md)、[发布者信号定位](qt_monitor_client_stage7_publisher_term.md)、[安装版录像控制](qt_monitor_client_stage7_installed_controls.md)和[许可来源边界](qt_monitor_client_package_provenance.md)。

## 明确延期或不做

- Windows、H.265：用户确认后续适配，当前不作为 Linux H.264 首版门禁。
- 独立广播产品/UI：已取消；对讲使用的内部 Broadcast 协议控制已经实现，不列为待开发广播界面。
- 中心录像/VOD：本轮没有该需求；设备录像和 Qt 本地录制不等于中心存储服务。
- 不恢复 GOP replay、通用媒体历史、viewer 反向关键帧控制或无限自动重连。

历史阶段文档继续保留原受测 HEAD、失败和未验范围；当前状态优先查本文和最新阶段收口表，不覆盖历史来制造“全部通过”。
