# 时段漂移

- RTMP 6500，同一服务端 ELF：`cap2-rtmp/round-002`（10-24 00:32）20.59 Gcycles/s、用户态 2.89 核；`cap6-rtmp-confirm`、`ab1-*`（04:20～05:00）16.55～16.80 Gcycles/s、用户态 1.76～1.85 核。
- `ab1` 在同一时段交替 6 轮：旧运行包（68a22ae，cap2 所用）、新运行包、新运行包+旧客户端，16.55～16.74 Gcycles/s，差异 <1%。排除工具版本。
- 同期 WHEP 3500：cap2（00:5x）19.29 G、cap6（04:3x）19.58～19.97 G，无明显漂移。漂移集中在访存密集的 RTMP（IPC 0.5～0.6），计算密集的 WHEP 不受影响，符合内存/LLC 延迟变化的特征（例如 uncore 频率），但 00:30 的 uncore 状态没有记录，无法证实。
- 客户端核上无外来负载（client_busy 与自有客户端进程 CPU 之差 ≤0.04 核），服务端核无其他进程。
- 05:15 起后台 `envlog.sh`（CPU 31）每 5 s 记录 uncore 频率、封装/DRAM 功耗、服务端核频率、封装温度。满载窗口内 uncore 2.4 GHz、封装 76 W（上限 100 W）、47 °C。
- 按时间排序（`raw/**/result.json`，满载 ≥2.6 GHz 的单协议 PASS 轮次）：
  - 00:00～01:40：RTMP 3.14～3.47 Mcycles/viewer·s（每 viewer 用户态 0.44～0.52 ms/s），FLV 3.18～3.28（IPC 0.53～0.56，1.75～1.77 Minstr/viewer）。
  - 02:09～02:20：RTSP 2.67～2.80（IPC 0.73～0.75）。
  - 04:20 以后：RTMP 2.52～2.59（IPC 0.58～0.62），FLV 2.57～2.66（IPC 0.68～0.70，1.77～1.81 Minstr/viewer）。
  - FLV 两段的指令数相同（差 <3%），周期差 25%：同样的工作，IPC 不同，即停顿周期变化。GB UDP（PSS 8 KB/viewer）两段都是 2.53～2.55，WHEP 两段 5.5～5.7，无变化。漂移只出现在每 viewer 有数百 KB 缓冲、访存密集的 TCP 输出上。
- atop 历史（`/var/log/atop/atop_20261024`，10 分钟粒度）：00:35～05:15 各窗口非测试进程 CPU 合计 868～3056 tick/10 min（≤0.05 核，02:55 窗口含 apt-get/appstreamcli），没有外部负载；内存空闲 12～19 GB、page cache 60～70 GB，无换页。
- 结论：漂移来自主机内存子系统状态（uncore 频率、DRAM 温度/刷新等无法回溯的因素），原因未确定。RTMP/FLV/RTSP 的周期成本存在约 ±12% 的时段不确定度，对应容量 6500～8500 的区间。
- 处理：RTMP 容量按当前时段重测（`cap7-rtmp`）；其他协议用确认轮次与早期轮次比较周期数，偏差 >5% 的以确认轮次为准。
- 06:00 起在队列中插入 7 个 RTMP 6500 哨兵轮次（`sn1`～`sn7`，带 perf stat），与 envlog 对照，判断漂移是否复现。
